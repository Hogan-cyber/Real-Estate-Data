# HKMA API migration

User scope: collect HKMA data primarily from the official API; official PDF
supplements are allowed when the API is incomplete. Keep existing indicator IDs,
units, historical coverage, reader/cache behavior and daily HIBOR source unchanged.

Design: use the mortgage survey (new and old segments), adjusted money supply
(new segment), and negative-equity APIs. Validate JSON, dates, numeric units,
pagination and duplicate periods. Keep official workbooks as a recovery source
for API failures or historical gaps. Inspect the latest official release date;
download its PDF only for missing fields/periods or API failure. API observations
have priority. Negative-equity delinquency remains a PDF supplement. Record the
actual source URL and field, raw responses, recovery events and coverage checks.
Never publish a truncated history as a successful update.

1. Add failing tests for mappings, percent units, missing values, pagination,
   population breaks, API precedence, PDF supplements and failed-source handling.
2. Implement the adapter and collection flow; document source selection and
   expose collection diagnostics in the published status JSON.
3. Run extraction/export/reader tests and a real collection. Compare the new
   HKMA rows with the previous published snapshot and inspect differences.
4. Request an independent code review, address findings, publish only scoped
   changes to GitHub, then verify the cloud run and released dataset.

Related investigation: Centaline's downloaded mortgage-category table reaches
January 2007 but explicitly covers HKMA-authorized financial institutions, not
all money lenders. Do not use it as an all-lender total. Separate money-lender
reports have verified annual data from 2011; monthly continuity is unconfirmed.
